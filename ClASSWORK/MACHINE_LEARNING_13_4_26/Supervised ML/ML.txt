20/4/26

Error : Difference between actual and predicted data.
MSE(Measured Square Error) : if 0 then model is perfect, if 0.7 to 0.8 then low/average model, if very high value then poor model. There is no fixed range of mse value, it depends on the number of dataset.
-> If there are multiple teams working on the same data(different parts of that data are given to different teams) and then whichever team gets the lowest mse, that model will be passed ahead.
RMSE : Root of MSE.
Confusion Matrix : 
   True Positive(TP) : Actual and model output is positively correct
   True Negative(TN) : Actual and model output is negatively correct
   FP : Actual is negative but Model says positive
   FN : Actual is positive but Model says negative

R^2(Accuracy Score) : ranges from 0 to 1 (It gives the accuracy of the model), eg, if 70% accuracy then R^2 is 0.7, 1 means perfect.
If the accuracy is low then we should do following things to increase it.
   -> Change the Dataset
   -> Change the model

29/4/26

API : The first method is it can be directly deployed in our server and the second method is through a pipeline.
In first method whenever we change a code at that time we have to update and deploy it again and again on aws and in pipeline we have done automation so we do not need to do all process again and again.
For pipeline we use github action and jenkins. The main difference between both is that in jenkins we create our own infrastructure.
When we push our code changes after that the automation is started.
In automation, the first step is merging all the code in a single file known as build file (eg, .exe file). After it is successfully built, it is given to aws to save changes (deploy it) otherwise it gives error.
In this automation, different types of testing is done, namely unit, integration and end to end testing. After successful testing of all this 3 tests it will make build file otherwise it will give error.
After making build file, Smoke testing and sanity testing are done, Smoke testing tests if the build is made properly or not, and in sanity testing it tests whether all the functionalities in build file works properly or not. In sanity testing, suppose we had a build file already made then the new functionalities will be checked with build file whether it works or not in that old file.
We can also make requirements file in which python==version, fastapi==version and lib==version are mentioned, we need to download all those to make the project run.
Advanced automation includes docker and kubernetes, docker is a OS level virtualization platform (image file) in which all the files including the project file, dependencies, requirements are stored in a single container and kubernetes has multiple containers like this.


Monolithic Architecture : It has 1 project, 1 port (server), i database but it has multiple api.
Microservice Architecture : Eg, zomato has admin, customer, hotel, rider and this all have their own servers and their requests are send to their respective servers.
Main difference is monolithic has a single server whereas microservice has multiple servers.

1/5/26

Testing Server : While the project is building it remains in this server and after all the testing is done it is uploaded to production server.
Production Server : It means we have now done the project live.

Types of testing : 
1. Alpha test : In this the project/AI model is given to all in house members of the company to use for some days and if there is any bug then it is being resolved and then comes beta testing.
2. Beta test : In this test the project/AI model is being launched in some areas to use it and if any bug then it is being resolved and after that it is being launched as final version.

On the server side, monitoring is being done, if any user faces any error then it is being stored in log file, multiple user having errors is being stored in this log file and then the errors in this log file is being resolved.

We use Cors when there is a server conflict, suppose backend runs on 8000 and frontend runs on 4000 then it does not connect so we use cors to solve this conflict.
